单聊消息序号：为什么不用 Redis INCR

张

阿张

后端工程师 · 32 篇文章

+ 关注（V1.1）

单聊的 messages.id 是全局自增，多实例并发写入时，事务提交顺序与 id 顺序可能不一致——客户端会看到乱序。会话内需要一个严格单调的 seq。

解法：把序号分配塞进行锁

UPDATE conversations
   SET seq_counter = LAST_INSERT_ID(seq_counter + 1)
 WHERE id = ?;

SELECT LAST_INSERT_ID();
整个过程在一条 UPDATE 的行锁内完成，应用层不需要分布式锁，Redis 重启也不影响。

LAST_INSERT_ID(expr) 是 MySQL 内置能力：执行后把 expr 记录为当前连接的 last_insert_id，随后取回。事务失败时 seq_counter 随事务回滚，不产生空洞。

并发发送的实测结果：10 路并发、重复 100 次，seq 始终为 1..10 连续无空洞。
